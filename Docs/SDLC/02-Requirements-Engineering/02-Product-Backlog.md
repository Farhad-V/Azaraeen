# Product Backlog

Use the agreed scope and the requirements to identify and review backlog items.


## Backlog

## Purpose

Manage proposed features, improvements, defects and technical work against the agreed MVP and product direction. A requirement is not automatically a completed or scheduled work item.

## Work-item fields

Record title, user/problem value, linked requirement or decision, acceptance criteria, dependencies, priority when agreed, and status. Use the previously discussed workflow: Ready, In Progress, Review & Testing, Done.

## Source of truth

The functional baseline supplies required behavior; the acceptance/traceability document links criteria and verification. GitHub Issues/Kanban can hold the working items when configured; this file does not claim those issues exist.

## Current items

A detailed itemized backlog and priority order have not yet been established. Proposed additions require Samira's scope decision; no dates or individual assignments are inferred.


## Epics and user stories

## Purpose

Organize the existing functional baseline into owner content/publication, visitor access, access requests, application archiving and bilingual presentation.

## Topics and outputs

Write selected stories with actor, goal and value; link FR identifiers and acceptance criteria rather than repeating the entire specification. Example: as Samira, generate access from an application draft so the link/password can be placed in the resume before submission.

## Boundaries

A story is a planning/communication view of a requirement, not a new feature or an additional source of conflicting behavior.

Detailed artifacts and evidence are pending unless explicitly stated above. This outline does not establish a completed assessment or implementation.

## Recording changes

For a new decision or question, record its identifier, context, options, decision/status, rationale, affected sources and any superseded decision. Leave unknowns explicit. Detailed architecture decisions remain in Architecture Decisions; link them here when product impact warrants it.
