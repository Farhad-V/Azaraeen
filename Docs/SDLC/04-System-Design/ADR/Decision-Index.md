# Architecture Decision Index

Use the architecture decision record for the current positions and open technical decisions.


## Architecture decisions

Record significant decisions that affect the system or software structure. Link the relevant System Architecture and Software Architecture views. Stack-specific decisions belong in the Technology category and should be referenced here when they influence architecture.

## Decision record

For each decision, record its context and requirement links, alternatives, chosen approach, rationale, consequences and review status. Record a decision as approved only after agreement; keep proposals distinguishable from approved decisions.

## Current decisions

No technical architecture decisions have been approved or recorded yet. The current hosting is a constraint to assess, not evidence that a particular architecture is supported.

## Decision ownership

Use a stable decision identifier when recording a significant architecture choice. Stack choices remain in Technology; link to them instead of duplicating their rationale. Decision records may be proposed, accepted or superseded and should link to the decision they replace.
