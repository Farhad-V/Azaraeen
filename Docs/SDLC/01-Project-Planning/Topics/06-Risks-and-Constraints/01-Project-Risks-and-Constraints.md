## 10. Risks, assumptions and constraints

Likelihood and impact have not been scored; these are analysis items, not verified defects.

| Risk or dependency | Treatment |
|---|---|
| Hosting compatibility | Verify runtime, database, protected file delivery and deployment before selecting a stack. |
| Email automation | Define receipt detection, acknowledgement and approval-triggered delivery separately from manual application archiving. An email composer link cannot provide these alone. |
| Translation meaning, confidentiality and cost | Retain owner review/manual editing and assess provider/data handling before integration. |
| Exposure of private files or credentials | Design access checks, secure credential handling and restricted archive storage. |
| Loss of submitted versions or history | Preserve archived versions and define backup, restoration and retention. |
| Resume not yet uploaded | Resolve visitor behavior in requirements; do not assume silent substitution. |
| Content copying or credential sharing | Avoid promising copy prevention; expiry cannot retract content already delivered. |
| MVP expansion | Keep scope and exclusions visible and evaluate additions before including them. |

Assumptions: one personal portfolio, owner-controlled access and preference for existing hosting subject to suitability. File limits and case-study quantity remain unresolved rather than invented.
